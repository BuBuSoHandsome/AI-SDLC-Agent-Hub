# Grill 题库

动笔前对用户逐个追问的问题库。按类型组织；由浅入深、一次一个，问到完全 clarify 为止。
业务特定问题现场生成，不必拘泥于本题库。
（本题库为过渡方案，后续由 wiki/LLM 问题库替代，skill 内不维护增量。）

## 通用：按能力类型

### 查询类能力
- 这个数据，业务能容忍多旧？（实时 / 准实时 / 可容忍延迟——例如：客户刚还款，额度显示一小时前的，能接受吗？）
- 数据为空时页面显示什么？
- 这个数据谁是 owner？（同一字段多个系统都有时以谁为准）

### 提交类能力
- 客户提交两次，业务上意味着什么？（各计一笔 / 重复返回原结果）
- 提交后能否修改或撤销？可撤销窗口多久？
- 提交是同步出结果还是异步受理？（异步→页面显示"已受理"，结果如何触达客户）

### 通知类能力
- 通知丢失时，客户通过什么页面/入口感知结果？（兜底感知路径）
- 重复通知客户，业务上可接受吗？
- （重发机制本身属于下游系统实现，不问；但送达要求要写进依赖清单）

## 银行场景

### 账务与状态
- 客户看到的状态与账务真实状态如何映射？（已受理 ≠ 已记账 ≠ 已清算）
- 哪些结果 T+1 才确定？页面如何表达？

### 风险合规
- 本功能触发 KYC / AML / 适当性 / 双录吗？前置校验在哪一步？
- 哪个操作需要强认证（短信/人脸/令牌）？
- 页面上哪些字段要脱敏？
- 哪些操作必须留痕可审计？（协议签署、要约确认）

### 渠道
- Mobile 和 AEM 行为一致吗？差异是有意的吗？
- 渠道限额有差异吗？限额值是否可配置（不写死端上）？

### 运营外露
- 有没有人工审核环节？（有→页面需要"审核中"状态）
- 驳回时，给客户看的原因文案从哪个字段来？

## 流程与分支
- 每个分支的走向都闭环了吗？（拒绝/取消/超时后去哪，不能只有 happy path）
- 客户中途退出后再次进入，从哪开始？（重新判定 / 恢复草稿）

## 边界确认
- 这个功能调用哪个后端服务？（问到服务名为止，内部实现不追问）
- 该后端服务现有能力够用吗，还是需要改造/新增？
