# Digital Solution Design 自查清单（兜底）

Grill 环节是主力，本清单是兜底。产出后逐项核对。

## 完整性
- [ ] 每个需求条目都能映射到某个功能点（§2.2）
- [ ] 每个功能点都标了实现方、依赖系统、依赖类型
- [ ] 六视角有实质发现的已写入 §2.2「六视角发现」列
- [ ] 非功能需求已提取（§2.3）

## 边界与形态
- [ ] 全文无 endpoint/URL/方法/错误码表/component 选型
- [ ] 没有为后端内部实现（DB/MQ/批处理/重发机制）做设计
- [ ] 业务规则没有写死在端上；限额等参数可配置
- [ ] 用不上的章节已删除，无空章节
- [ ] §1「方案一句话」能向非技术干系人讲清楚

## 能力设计（§6）
- [ ] 查询类能力都标了数据时效要求
- [ ] 提交类能力都标了重复提交语义
- [ ] 通知类能力都标了送达兜底路径
- [ ] 涉及资金的能力都写了账务状态映射
- [ ] 每个能力/字段标了 阻断/降级 及降级展示形态
- [ ] 敏感字段标了脱敏规则
- [ ] 关键链路时序图已画，分支（拒绝/失败/超时）走向闭环

## 渠道（§4/§5）
- [ ] 页面清单每行都能让 TL 直接拆任务（改动类型 + 一段话内容 + 所需数据可追溯）
- [ ] 显示类页面的每个展示字段能追溯到某个能力的输出
- [ ] Mobile / AEM 差异都有说明且是有意的
- [ ] 页面状态覆盖中间态（审核中/已受理）与空态/加载态/异常态

## 依赖与交接（§7/§10）
- [ ] 每条依赖标了 复用/改造/新增 + 状态
- [ ] 通知类依赖写明送达要求
- [ ] Grill 未获答案的问题全部进了 §10 Open Items
- [ ] 风险合规项已标一票否决且先于技术方案确认
