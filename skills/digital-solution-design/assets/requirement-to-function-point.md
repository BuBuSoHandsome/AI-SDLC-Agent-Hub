# 银行需求功能点拆分

## 目标

把银行需求文档整理成业务功能点表格，供后续 Solution Design 使用。

只写原文和用户已经确认的内容。不要自行增加银行惯例、监管规则、系统处理或新业务。

## 工作步骤

### 1. 先读完整篇需求

先不要逐行拆分。先找出：

- 客户是谁。
- 客户通过什么渠道办理。
- 当前处于哪个业务阶段，例如线索收集、正式申请、审批、放款、交易或贷后管理。
- 客户要完成什么。
- 银行要获得什么。
- 出现什么结果才算办理完成。

用这些信息限制拆分范围。不要把后续业务阶段的内容加入本次功能点。

### 2. 先澄清影响拆分的问题

检查原文是否有不清楚、前后矛盾或缺失的内容。

如果问题会改变功能点的数量、范围、名称或业务结果，先向用户提问，再输出表格。不要猜测，也不要另设“待确认问题”字段。

提问时：

- 尽量一次问完所有重要问题。
- 引用相关原文。
- 说明需要确认什么，以及它会影响哪项拆分判断。
- 可以提供具体选项，方便用户回答。
- 用户回答后，把回答作为本次拆分依据。

如果问题只涉及字段长度、提示文案、按钮样式或其他页面细节，而且不影响功能点拆分，不要打断用户。

### 3. 按办理顺序列出主要过程

列出客户和银行从开始到结束的主要过程。再记录人工协助、资料更新、失败处理等辅助过程。

这些过程用于帮助理解需求。不要直接把每个过程都当成功能点。

### 4. 用银行维度检查是否有遗漏

按原文适用情况检查以下维度：

- 客户与渠道：谁能办理，从哪里进入，需要满足什么访问条件。
- 产品与披露：客户需要查看哪些产品资料、申请指引和业务说明。
- 业务信息采集：银行需要收集哪些客户意向、申请信息或交易信息。
- 客户资料与数据安全：资料如何预填、核对、更新和保护。
- 客户授权与合规：客户需要同意什么，未同意时如何处理。
- 业务流程与受理：如何提交、校验、受理、改变状态和确认结果。
- 风险与控制：是否涉及身份核验、限额、反欺诈或其他风险检查。
- 资金与账务：是否涉及费用、扣账、记账、结算、退款、冲正或对账。
- 银行运营与客户服务：是否需要人工跟进、复核、异常处理或客户协助。
- 通知与凭证：是否需要通知、回单、参考编号或确认信息。
- 数据与系统：数据从哪里来，需要交给哪个系统。

只使用与原文有关的维度。不要为了凑齐维度增加功能点。

### 5. 把完成同一件事的内容放在一起

按业务结果归并原文内容。

如果多个字段、规则、操作和异常处理共同完成同一个业务结果，把它们放进同一个功能点。

例如，手机号码预填、脱敏、缺失检查和更新引导，都是为了确认银行能够联系客户，可以归入“客户联系资料确认与维护引导”。

只有在参与角色、业务对象、业务结果或处理责任明显不同时，才拆成不同功能点。

### 6. 检查每个候选项是否真的是功能点

逐个检查：

- 是否产生明确的业务结果。
- 是否说明客户或银行需要完成什么。
- 删除后是否会缺少一项业务能力。
- 是否只是另一个功能点中的字段、规则或页面操作。

不要把以下内容单独作为功能点：

- 字段或静态文案。
- 页面展示或页面跳转。
- 按钮、弹窗或单次点击。
- 默认值、格式、必填或范围校验。
- 错误提示或一般异常场景。
- 数据预填、脱敏或展示要求。

如果某项内容本身构成独立的银行服务能力，可以单独作为功能点。

不要预先规定功能点数量。保持各功能点的粒度大致一致。

### 7. 用清楚的业务语言命名

名称直接说明处理什么、做什么。可以使用“业务对象＋业务动作＋业务结果”。

使用“客户同意采集与提交控制”，不要使用“勾选同意框”。

使用“线索提交与受理确认”，不要使用“点击 Continue 并跳转页面”。

## 输出表格

完成必要澄清后，只输出一个 Markdown 表格，不要展示内部分析过程。

表格固定使用以下字段：

| 编号 | 银行维度 | 功能点 | 功能点描述 | 功能细则 | 原文引用 |
|---|---|---|---|---|---|

按以下要求填写：

- **编号**：使用 FP-01、FP-02……。
- **银行维度**：填写最主要的一个维度；必要时增加一个次要维度。
- **功能点**：填写清楚的业务能力名称。
- **功能点描述**：用一句话说明谁做什么，以及得到什么业务结果。不要写金额上下限、默认值、按钮或页面跳转等细节。
- **功能细则**：填写该功能点包含的字段、业务规则、客户操作、系统校验、异常处理和页面跳转。只写原文和用户已经确认的内容，不重复功能点描述。
- **原文引用**：逐字摘录支持该功能点的原文，并注明章节或表格位置。不要改写或翻译。需要时可以引用多条，但不要复制整篇需求。

使用用户的语言填写表格，原文引用保留原文语言。

## 输出前检查

- 每个功能点都有明确的业务结果。
- 没有把按钮、字段或单个校验规则单独当成功能点。
- 功能点描述没有重复功能细则。
- 每个功能点都有对应的原文引用。
- 原文引用逐字准确，并标明位置。
- 没有加入原文和用户回答中不存在的内容。
- 没有为了使用所有银行维度而增加功能点。
